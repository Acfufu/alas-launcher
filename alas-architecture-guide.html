ALAS 项目架构图解报告

面向初级开发者的图文解说：alas-launcher（Rust/Tauri 启动器）+ AzurLaneAutoScript（Python 本体）如何组装成一个自动玩游戏机器人
Tauri v2 / Rust Python 3.7+ FastAPI / PyWebIO ADB 自动化 多进程调度 全平台（Win / macOS / Linux）

0. 先看结论：这个项目是什么

30 秒速览，看完再往下走。

项目由两个仓库组成，各司其职：

  • Rustalas-launcher：一个用 Tauri 写的桌面「外壳」。它负责：找到 ALAS、更新 ALAS（并打上「控制 API」补丁）、启动 ALAS、把网页装进自家窗口、接管文件下载；macOS 上还提供托盘任务速览与原生通知。它本身不含任何游戏逻辑。
  • PythonAzurLaneAutoScript（ALAS 本体）：真正的机器人大脑。一个跑在本地 http://127.0.0.1:22267 的 Web 服务 + 调度器 + 一堆认图/点屏幕的模块。它不知道自己被启动器包着，它只认「有人用浏览器打开了我」。
  • 设备层：模拟器 / 手机通过 ADB 暴露给 ALAS。ALAS 截图、识别、点击，操作的是游戏画面。
一句话总结工作路径：用户双击启动器 → 启动器注入环境 + 拉起 Python Web 服务 → 启动器窗口变成「浏览器」访问这个服务 → 你在网页里点「开始」→ WebUI 开一个子进程跑调度器 → 调度器按配置挑任务 → 任务模块用 ADB 操作模拟器里的游戏。

1. 全景图：ALAS 本体是一个方块，外面怎么「调用注入」

这张图是整个报告的地图。先看方块，再看箭头（箭头 = 调用/注入方向）。

图 1：整体工作路径。橙色 = 启动器（外部），蓝色 = ALAS 本体（被调用方），绿色 = 配置，紫色 = 设备，黄色 = 游戏。
「ALAS 本体是一个方块」是什么意思：ALAS 是一个自包含的 Web 服务。它不依赖启动器——单独开终端跑 python gui.py，再用任何浏览器打开 127.0.0.1:22267 也能完整使用。启动器只是「替你把浏览器、Python、Git、ADB 都准备好」的外部包装，另经一条 控制 API（更新后自动打的补丁）驱动调度器启停。这就是方块比喻：方块内部自洽，外部通过固定接口（端口 + 子进程 + 环境变量 + 控制 API）进出。

2. 双击启动器之后：8 步时序

跟着箭头走一遍启动流程。每一步都对应 alas-launcher 里的真实代码。

  1. 启动器进程开始。入口 src/main.rs。Windows 上先隐藏控制台窗口（window_util.rs）。
  2. 注入环境变量（setup_environment()，setup.rs）。把 toolkit/bin、toolkit/libexec/git-core 塞进 PATH，把 toolkit/lib 塞进 LD_LIBRARY_PATH，然后 chdir 到 ALAS 根目录。这样后面不管调 python、git、adb 都找得到——绿色版工具链，不污染系统。
  3. 读部署配置：get_deploy_config() 解析 config/deploy.yaml，取出 Deploy → Webui → WebuiPort（默认 22267）。这个端口就是后面所有连接的「插座」。
  4. 弹 splash 窗口，后台线程干活（setup_alas_repo()）：先 atomic_failure_cleanup 清理上次中断写入的残留临时文件，再跑 python -c "deploy.git.GitManager().git_install()"——复用 ALAS 自带的 Git 更新逻辑，进度实时显示在 splash 上。更新完成后打「控制 API」补丁（patch.rs）：先校验锚点（module/webui/fastapi.py 的 asgi_app()，2022-04 起未动），校验通过才落地；失败则打降级标记——托盘调度器开关禁用，启动照常。
  5. 拉起 Python 后端（ManagedBackend::new()，backend.rs）：设置环境变量 ALAS_LAUNCHER_PID=启动器进程号，然后 spawn("python", ["gui.py", "--host", "127.0.0.1", "--port", "22267"])，并放进一个进程组（方便整组杀掉）。
  6. 等端口就绪：每 100ms 尝试 TcpStream::connect 连 127.0.0.1:22267，最多等 60 秒。连上了说明 uvicorn 起来了。
  7. 主窗口登场：销毁 splash，把主 WebView 导航到 http://127.0.0.1:22267/。启动器的窗口从此「变身」成浏览器，页面内容其实来自 Python。
  8. 页面注入 JS（page_load_injector）：页面加载完成后执行一段脚本——把 window.saveAs 换成「读取 Blob → base64 → 调 Tauri 的 save_as 命令 → 弹 Rust 原生保存对话框」的实现。同时拦截浏览器「后退」。这就是最典型的一处「外部注入」。用户看到的界面与原生程序无差别。
冷知识：上游 ALAS 官方客户端是 Electron（webapp/packages/main/src/index.ts），干的事一模一样——用 PyShell 拉起 gui.py，再用窗口装网页。所以这个启动器 = 「用更轻的 Tauri 重写 Electron 的壳」。理解它，就理解了为什么启动器里几乎没有业务代码。

3. ALAS 本体内部解剖：从网页到点屏幕

把一个方块拆开看：里面的进程层次，以及「点一下开始」之后数据怎么流动。

图 2：ALAS 本体解剖。一个「开始」按钮背后，是 WebUI 进程拉起的独立任务子进程；任务子进程里才是完整的调度器循环。

为什么用「子进程」而不是「子线程」跑任务？

  • 隔离：任务卡死、内存爆炸，杀掉子进程即可，WebUI 不受影响。
  • 多开：每个配置实例（alas、alas2…）一个进程，互不干扰。
  • 更新：更新 WebUI 后重启 uvicorn，任务进程可以保留继续跑。
  • 代价：进程间通信（日志、停止信号）要用 multiprocessing 队列/事件，代码略绕。

日志是怎么从子进程流回网页的？

  • 子进程里 set_func_logger(func=q.put)：把日志包装成对象丢进 multiprocessing Manager.Queue。
  • WebUI 进程里 _thread_log_queue_handler 线程持续取队列。
  • RichLog.put_log() 每 0.25 秒把新日志刷到页面控制台。
  • 停止信号走 threading.Event（如更新前优雅退出），强杀走 process.kill()。

4. 机器人怎么决定「现在干什么」：调度器

ALAS 是任务驱动的：每个「任务」是一个配置键，带一张调度卡。看一个真实的配置片段就懂了。

# config/alas.json（每个机器人实例一份）
{
  "Campaign": {            // 推图任务
    "Scheduler": {
      "Enable": true,      // 开关
      "Command": "Campaign", // 对应 alas.py 方法名
      "NextRun": "2026-08-13 12:00:00" // 下次执行时间
    },
    "Campaign_Name": "12-4",
    "Campaign_Mode": "normal"
  },
  "Daily": { "Scheduler": { "Enable": true, "Command": "Daily", "NextRun": "05:00" } },
  "Event":  { "Scheduler": { "Enable": true, "Command": "Event",  "NextRun": "12:00" } }
}

你在 WebUI 的「调度」页改的就是这些字段。保存 = 写回这个 JSON。

调度循环（alas.py 的 loop()）

  1. 检查停止事件、服务器维护状态。
  2. config.get_next()：扫所有任务，Enable=true 且 NextRun <= now 的进「待办」；还没到点的进「等待」。
  3. 用 SCHEDULER_PRIORITY（config_manual.py 里的优先级链：Restart > 日常类 > 推图类）排序。
  4. 没有待办 → 按 Optimization_WhenTaskQueueEmpty 挂机（回主界面 / 关游戏 / 原地等），期间监听配置改动，改了立刻重新挑任务。
  5. 挑到任务 → run(inflection.underscore(Command))：Campaign → self.campaign()。
  6. 任务方法内部：模块类(config, device).run()。推图走 CampaignRun → 关卡文件 → CampaignBase 战斗循环。
  7. 出问题：游戏没开/卡死/点错 → config.task_call('Restart') 强制重启游戏并回到循环；脚本级错误 → 记录失败次数，连续 3 次失败 → 通知并退出。
「任务名 = 方法名」是 ALAS 的可扩展核心：想加一个新任务，只需要写一个类并给它一个 run()，在 alas.py 加一个同名方法，然后在 WebUI 的配置里就会多出这个任务的调度卡。关卡内容（battle_1、battle_boss…）则由 campaign/ 目录下的关卡文件按约定实现，无需改核心。

5. 配置都住在哪：两类文件、两套读写

新手最容易混淆的两份配置，分清它们就成功了一半。

文件谁读谁写内容特点
config/deploy.yaml 启动器（端口）、gui.py、部署工具 WebUI 的 DeployConfig（改属性即自动写回） Deploy 段：Git（分支/镜像）、Python、Adb、Ocr、Update（自动更新）、RemoteAccess、Webui（Host/Port/Password） 「这机器怎么跑」——安装、更新、网络相关
config/<名字>.json 任务子进程（AzurLaneConfig） WebUI（AlasGUI 防抖批量保存，经 ConfigUpdater 迁移） 每个任务的参数 + Scheduler 调度表。如 alas.json、alas2.json 「机器人干什么」——每个实例一份，可多开

小坑：本仓库里 config/deploy.yaml 在 macOS 上是 Finder 别名（指向已安装的 App），别直接编辑它；真正的模板在 deploy/template 和 deploy/Windows/template.yaml。

6. 「外部调用注入」到底注入了什么：6 类注入点

回到最初的问题。外部（启动器）对 ALAS 本体的全部接触方式，一共六类。这张表是启动器的「接口文档」。

#注入类型方向机制作用
1环境变量注入 启动器 → Python 子进程 setup_environment() 把 toolkit/bin、toolkit/libexec/git-core 加入 PATH，toolkit/lib 加入 LD_LIBRARY_PATH；再设置 ALAS_LAUNCHER_PID 让「绿色版」git/python 随处可用；ALAS_LAUNCHER_PID 是进程血缘标记，退出时按它清扫泄漏进程
2子进程注入 启动器 → gui.py ManagedBackend 用 Command::new("python").args(["gui.py","--host","127.0.0.1","--port","22267"]) 拉起，放入进程组；60 秒轮询 TCP 端口确认存活 把 Python Web 服务「装进」启动器生命周期：启动器关，Python 跟着死
3网络调用 WebView ↔ gui.py（双向） HTTP 访问 http://127.0.0.1:22267/；WebUI 是 ASGI 服务（uvicorn + PyWebIO），返回页面；页面里按钮再发请求控制任务 界面与逻辑解耦——换任何浏览器都能用，启动器只是恰好内嵌了一个
4JS 注入 启动器 → WebView 页面 page_load_injector：页面加载完成事件里 webview.eval() 一段脚本，覆盖 window.saveAs，把 Blob 转 base64 后调 Tauri save_as 命令，走 Rust 原生保存对话框；顺带拦截浏览器后退 让网页里的「导出配置/日志」落到用户真正想存的位置，体验和原生 App 一致
5配置文件注入 双向 启动器读 config/deploy.yaml（端口）；WebUI 写 deploy.yaml 与 config/*.json；任务子进程读 JSON 的 Scheduler 段 唯一的「长期记忆」：重启后配置不丢，调度表决定今天干什么
6控制 API 注入 启动器 → WebUI（HTTP） 补丁新增 module/webui/control_api.py（挂载于 4.3 年未动的 fastapi.py）；托盘调 POST /api/alas/{name}/scheduler/start|stop，与网页按钮调同一个 ProcessManager；更新后自动应用，锚点校验失败即 fail-closed 降级 macOS 托盘启停调度器的稳定通道——替代早期「伪装浏览器点按钮」的脆弱方案（版本锁死、回调 1 秒时效）
刻意没有做的注入（也是它的卖点）：不注入游戏进程、不改游戏文件、不 hook 内存。ALAS 是纯「读屏幕 → 判断 → 点屏幕」的外挂式自动化，因此换引擎（WebView/Electron/浏览器）都不影响本体——方块内外只靠上面的 6 类接口通信。

7. 进程生命周期：从双击到退出

运行期间系统里同时活着的进程，以及它们怎么被优雅（或暴力）地收掉。

进程谁创建干什么怎么退出
alas-launcher（Rust）用户双击 窗口、WebView、git 更新、进程管家 用户关窗口 → RunEvent::ExitRequested → 调 backend.terminate()；重复启动时 single-instance 插件只聚焦已有窗口
python gui.py 监督者ManagedBackend EnableReload 时监视 uvicorn 子进程，收到 restart_event 就重启 随启动器退出（SIGTERM 进程组 → 5 秒后 kill）
uvicorn（ASGI 服务）gui.py 提供 WebUI 页面与接口 restart_event（更新后）/ 随进程组被杀
任务子进程ProcessManager（每个实例一个） 跑 alas.py 调度循环，操作模拟器 点「停止」→ process.kill()；更新前 → 通过 Event 优雅退出；兜底：启动器 Drop 时扫所有进程环境变量，凡带 ALAS_LAUNCHER_PID=当前启动器 pid 的一律杀掉——防「孤儿」

9. 术语表：初级开发者速查

Tauri
用系统自带 WebView + Rust 做桌面应用的框架。比 Electron 轻（没有打包整个 Chromium）。
WebView
系统级网页渲染组件。macOS 上是 WKWebView，Windows 上是 WebView2（Edge 内核）。启动器窗口 = 一个 WebView。
ASGI / uvicorn
Python 异步 Web 服务器标准/实现。gui.py 用 uvicorn 把 ALAS 的 WebUI 跑成本地 HTTP 服务。
PyWebIO
用 Python 写网页交互的库。ALAS 的整个管理界面都是它渲染的（FastAPI 适配版）。
multiprocessing.Process
Python 真·子进程（不是线程）。ALAS 每个机器人实例一个，崩溃隔离、可多开。
ADB（Android Debug Bridge）
安卓调试桥。ALAS 通过 adbutils 库驱动它完成截图、点击、输入——这是它对游戏唯一的「手」。
模板匹配 / OCR
ALAS 的「眼睛」：模板匹配 = 拿 assets/ 里的截图小图在屏幕上找位置；OCR = 把屏幕上的文字读出来（cnocr/MXNet）。
IPC
进程间通信。本项目的 IPC 有四套：启动器↔WebView 走 Tauri 命令（invoke）；启动器↔WebUI 走控制 API（HTTP）；WebUI↔任务进程走 multiprocessing 队列/事件；网页↔服务走 HTTP。
控制 API
启动器给 ALAS webui 打的补丁：把 ProcessManager 启停暴露成 HTTP 端点（/api/alas/…），托盘不再逆向网页 DOM。锚点 fastapi.py 4.3 年未动，锚点校验失败即降级禁用，不阻塞启动。
调度表（Scheduler）
config/*.json 里每个任务的 Enable/Command/NextRun 三件套，是「机器人几点干什么」的唯一依据。
防抖（debounce）
WebUI 收集 1 秒内的配置修改再批量写盘，避免你拖动一个滑块就写几十次文件。
进程组（process group）
backend.rs 用 command-group 把 gui.py 及其子孙捆成一串，一条 SIGTERM 全组收掉。
本报告基于对 alas-launcher（Tauri v2）与 AzurLaneAutoScript（master 分支，HEAD 81ccf63b）实际源码梳理生成；启动器侧描述已对齐路线 C 改造目标架构（控制 API 补丁 + macOS 原生通知）。图中文件名/函数名均可在仓库中直接检索验证。
