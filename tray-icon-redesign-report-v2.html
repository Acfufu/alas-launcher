方案详情 Proposals

N1雷达n1-radar

圆环 + 扫描扇 + 一个目标光点。托盘每 3 秒轮询一次调度器状态、启动前扫描残留进程——这个 launcher 的日常就是「扫描」，雷达是这一行为最直的图形化。

代码依据：src/tray.rs 的 3 秒轮询、stale_cleanup 的启动扫描、payload 里的 MASK_OS_RADAR

五版中独特性最高、与「常驻监视」语义咬合最紧；雷达扇形的方向性让图标有轻微动感。代价是与「航海」的品牌联想完全断开。

N2航线n2-route

起点、虚线航程、箭头终点。对应托盘菜单里那条「运行中 → 队列中 → 等待中」的任务链：主线图、委托、战术学院……按计划时间依次推进。

代码依据：tray-menu.png 的三态任务分组、每个任务的下一次调度时间

把「调度」这个最独特的功能画进了图标；但虚线在 16px 下密度偏高，是五版中对渲染尺寸最敏感的一版。

N3提示符n3-prompt

一个加粗的 >_ 提示符。剥掉所有航海包装，这个产品做的事就是：替用户把一条 Python 命令跑起来，并在菜单栏汇报结果。

代码依据：README workflow：初始化 → 更新 → 启动 gui.py → 就绪

对「脚本工具」的自我认知最诚实，脚本党一看就懂；但 >_ 几乎是终端类应用的公共符号，品牌独占性最弱。

N4电源n4-power

标准电源符号：缺口圆环 + 竖条。菜单栏里被点击最多的东西就是调度器开关（scheduler start/stop），图标直接长成那个动作。

落地方式 Integration

① 资产已生成

五个方向的 SVG 源与 32px / 64px(@2x) 模板 PNG 已写入 icons/proposals-v2/，纯黑 + alpha，程序化校验通过。

② 切换只需一行

tray.rs 中 include_image! 指向选中方案的 tray-icon.png，重新编译即生效。

③ 状态语义

每案均含描边「已停止」变体，可用 tray.set_icon() 在启停时切换，纯形状语义、无需颜色。
